# Research Evaluation Protocol

## Dataset integrity

Use M4 human labels, not M3 rule predictions, as ground truth. Preserve reviewer
IDs, uncertain labels, adjudication records, project fingerprints and source
file SHA-256 values. Exclude uncertain labels from binary training unless the
paper explicitly models uncertainty.

## Leakage prevention

- Split by complete project, never by method/class row.
- Keep the outer test project completely untouched during feature selection,
  hyperparameter selection and threshold selection.
- Perform grouped inner cross-validation only on training projects.
- For LOGO, repeat tuning after each project is held out.

## Metrics

Report accuracy only as a secondary measure. Include precision, recall,
specificity, F1, MCC, ROC-AUC, PR-AUC, Brier score and confusion counts.
For one-class held-out projects, mark ranking metrics unavailable rather than
inventing values.

## Aggregation

Report:

1. each held-out project fold;
2. macro mean across projects;
3. standard deviation and confidence interval across valid folds;
4. pooled micro metrics;
5. class distribution and support;
6. skipped folds and reasons.

Do not claim independent samples when many entities come from the same project.
Project is the primary generalization unit.

## Baselines

Compare ML models against:

- M3 literature/heuristic absolute rules;
- M3 project-percentile rules;
- a simple logistic model;
- the stronger selected model.

Use the same test projects and human labels for every comparison.

## Statistical analysis

For final publication, use repeated project-level splits where possible. For
paired model comparisons, compute metrics on the same projects and use a paired
procedure suitable for the number of projects. Clearly distinguish exploratory
normal-approximation intervals generated by M9 from confirmatory statistical
testing.

## Reproducibility

Record tool version, dataset manifest hash, model SHA-256, seed, feature order,
project assignments, software versions and hardware. Archive raw fold
predictions so future researchers can recompute metrics.

## M9 command

```bash
codesmell research summarize \
  models_m5/holdout_report.json \
  logo_m5/logo_report.json \
  -o paper_results
```

The command produces CSV tables, per-fold data, plots and a Markdown summary.
Synthetic demonstration results are for execution testing only and must never
be reported as research findings.
